# E5 생성 파이프라인 v2: 세 단계 생성

파일럿 1의 문제를 고친 생성 파이프라인 사양이야. Claude Code에서 그대로 구현할 수 있게 입력, 출력, 검사 규칙, 프롬프트, 파일럿 2 기준을 모두 적었어. 사전 등록 초안이 허용한 "파일럿 뒤 한 번의 수정"을 이 문서로 써.

> 구현: `src/e5v2.py`, `experiments/e5v2_*.py`, 프롬프트 `e5/v2/prompts/`. 구현에서 정한 세부와 사양과 다르게 한 점은
> `PREREG_E5.md` 6절에 적었다.
>
> 파일럿 2(2026-11-16)는 실패했다. 이 사양의 쌍(8절, 거리 1~2)과 뜻풀이(첫 뜻)는 파일럿 3부터 거리 0~1 쌍과 가장 흔한 뜻으로
> 바뀌었고, riddle 잘림과 S3 응답 읽기 두 곳이 완화됐다(`PREREG_E5.md` 6.4~6.5).
> 파일럿 3 뒤 S1 상한(아래의 30회)은 60회로 올랐고 생성기 후보는 32B만 남았다(`PREREG_E5.md` 6.6~6.7).

## 0. 파일럿 1 문제와 v2의 대응

| 파일럿 1 문제 | 원인 | v2 대응 |
|---|---|---|
| 말장난이 성립하지 않음 (관문 통과 0/56) | 한 프롬프트로 "w_a는 숨기고 들리게만"을 시킴. 모델이 w_a를 숨기면서 w_a 맥락도 같이 뺌 | S1에서 w_a 맥락을 숨김 없이 먼저 만들고, S2에서 코드가 w_a를 w_p로 바꿈 |
| w_a를 직접 씀 (49/124) | 모델이 말장난을 "두 단어를 같이 넣기"로 이해함 | **각 LLM 단계는 한 단어만 본다.** S1은 w_a만, S3는 w_p만 알아. 두 단어를 동시에 아는 건 코드뿐이야 |
| w_p를 빼먹음 (32/124) | 모델이 w_p를 비슷한 말로 바꿔 씀 | S2가 문자열 치환으로 w_p를 넣어. S3 결과는 끝부분이 그대로인지 코드로 확인해 |
| 형식 틀림 (27/124) | 한 줄 상황형에 수수께끼를 씀 | 형식마다 프롬프트를 따로 두고, 출력 모양을 코드로 검사해 |
| 후보 부족 (칸당 6.2개), JSON 깨짐 | 한 호출에 10개 요청 | 한 호출에 1개만 받아. 규칙 통과 후보가 10개 찰 때까지 다시 불러 |
| 규칙 위반 후보에서 고름 (9칸) | 통과 후보가 없을 때 전체에서 고르는 대체 규칙 | 대체 규칙을 없애. 규칙 통과 후보만 골라 |
| 연결 단어가 w_p 뜻을 굳힘 | w_p 이웃을 w_a 맥락 없이 줌 | w_p 이웃 단어는 S3(먼 주제어)로 옮겨. w_a 맥락은 S1이 만들어 |
| B0 엉터리 alt_word, 재탕 | 모델이 스스로 쌍을 댐 | 쌍 유효성 검사를 넣고, 재탕은 걸러내지 않고 따로 보고해 |
| P4 동점 → 첫 후보 | S_ratio가 80% 행에서 −1 | 고정 시드로 동점을 무작위로 가려. P4는 탐색 조건으로 내려 |
| 판정기가 w_p를 그대로 답함 (13%) | 답 제약 없음 | w_p와 같은 답은 실패로 쳐 |

## 1. 전체 흐름

한 칸 = (쌍 1개, 형식 1개). 형식은 수수께끼형(`riddle`)과 한 줄 상황형(`oneliner`) 두 가지야.

```
입력: (w_p, g_p), (w_a, g_a), 형식 f
  │
  ├─ S1  w_a 문장 쓰기   [LLM, w_a만 앎]   → ①  "...? A beagle."
  ├─ S2  바꿔 끼우기     [코드]            → ②  "...? A bagel."
  ├─ S3  w_p 주제어 넣기 [LLM, w_p만 앎]   → ③  "What kind of dog did the baker adopt...? A bagel."
  ├─ 최종 규칙 검사       [코드]
  ├─ A 채점 (②, ③ 모두) [Pythia-1.4B]
  └─ 조건별 고르기 (P1~P4)
```

규칙 통과 후보가 10개 찰 때까지 S1부터 반복해. S1 호출은 칸당 최대 30회야.

He의 이론에 맞춰 보면 이래:
- S1·S2가 **가까운 맥락**을 만들어. 말장난 자리 바로 앞이 w_a를 불러.
- S3가 **먼 맥락**을 만들어. 앞쪽 주제어가 w_p를 받쳐.

관문과도 이렇게 맞아떨어져:
- T̂_→ = w_a 조건은 S1·S2가 맡아.
- A_→ 문턱(두 뜻이 다 살아 있는 정도)은 S3가 맡아.

## 2. S1: w_a 문장 쓰기

**목적**: w_a가 문장 끝에서 자연스럽게 나올 수밖에 없는 평범한 문장을 만들어. 말장난을 시키지 않아.

**설정**: 온도 0.9, top_p 0.95, 최대 60토큰, 한 호출에 1개. 시드는 `cell_seed + attempt`로 정해.

프롬프트: `e5/v2/prompts/s1_riddle.txt`, `s1_oneliner.txt` (사양의 문구 그대로).

### S1 검사 (코드)

| 검사 | riddle | oneliner |
|---|---|---|
| 모양 | `Q:` 줄과 `A:` 줄이 하나씩, Q는 `?`로 끝남 | 한 문장, `?` 없음, 마침표·느낌표로 끝남 |
| w_a 횟수 | 정확히 1회. 단어 경계 기준, 대소문자 무시, **주어진 형태 그대로** | 같음 |
| w_a 위치 | 답의 마지막 두 단어 안 | 문장의 마지막 세 단어 안 |
| 길이 | Q ≤ 15단어, A ≤ 8단어 | ≤ 25단어 |
| 잘림 | 끝 문장부호 없으면 실패 | 같음 |

실패하면 이유를 기록하고 다음 시도로 넘어가.

---

## 3. S2: 바꿔 끼우기 (코드)

1. ①에서 w_a를 w_p로 바꿔. S1 검사를 통과했으니 w_a는 정확히 1회만 나와.
2. **대소문자**: w_a가 대문자로 시작하면 w_p도 대문자로 시작하게 해.
3. **관사**: 바로 앞 단어가 `a`/`an`이면 CMUdict로 w_p의 첫 음소를 보고 맞춰(모음이면 `an`).
4. **보호 구간 기록**: ②에서 w_p 두 단어 앞부터 끝까지를 `protected_suffix`로 저장해. riddle은 답 전체를 보호해. S3 검사에 써.

LLM을 부르지 않으니 실패는 없어. 단위 테스트로 대소문자, 관사, 구두점 붙은 경우(`bed.` → `bread.`)를 확인해.

## 4. S3: w_p 주제어 넣기

**목적**: 문장 앞쪽에 w_p 뜻을 받치는 단어를 넣어. 끝을 w_p 그대로 읽어도 말이 되게 하는 거야.

**설정**: 온도 0.7, 최대 60토큰. 검사에 실패하면 시드를 바꿔 한 번 더 불러. 두 번 다 실패하면 이 후보를 버려.

**힌트 단어**: w_p의 word2vec 이웃 상위 20개에서 다음을 빼고 5개를 줘.
- w_p의 굴절형
- w_a와 코사인이 0.3 이상인 단어. 힌트가 w_a 쪽 뜻을 가리키지 않게 하려는 거야.

프롬프트: `e5/v2/prompts/s3_riddle.txt`, `s3_oneliner.txt` (사양의 문구 그대로).

### S3 검사 (코드)

- **끝 보존**: ③이 `protected_suffix`로 끝나야 해. 비교 전에 공백과 대소문자를 정규화해.
- **수정 폭**: 보호 구간 앞부분을 ②와 단어 단위로 비교해(`difflib.SequenceMatcher`). 바뀌거나 들어간 단어가 1~4개여야 해. 0개면 주제어가 없으니 실패야.
- **w_p 횟수**: 표제어 기준으로 정확히 1회.
- **w_a 없음**: 표면형과 표제어 모두 확인해.
- **기록만 하는 진단 항목** (규칙은 아님):
  - 바뀐 단어 중 힌트 단어가 있는지
  - 바뀐 단어와 w_p의 word2vec 코사인 최댓값 (`topic_link`)

## 5. 최종 규칙 검사와 후보 채우기

③이 다음을 모두 통과해야 후보로 인정해.
- w_p 정확히 1회, w_a 없음 (표제어 기준)
- 형식 모양 일치 (S1 검사와 같음)
- 40단어 이하, 끝 문장부호 있음
- 같은 칸 안에서 중복 아님 (소문자화하고 구두점을 뺀 문자열 기준)

**채우기 규칙**:
- 통과 후보가 10개가 되면 멈춰.
- S1을 30회 불러도 10개가 안 차면, 있는 만큼 쓰고 `underfilled`로 표시해.
- 통과 후보가 0개면 이 칸의 P1~P4는 모두 "생성 실패"로 처리해.
- 규칙에 걸린 후보에서 고르는 대체 규칙은 **없애**.

## 6. A 채점과 고르기

**채점 설정**: PREREG와 같아.
- 청자 모델: Pythia-1.4B 베이스
- 후보 집합: C_union, γ = 1.0
- 같은 표제어의 확률은 더해
- π_←(왼쪽 문맥만), π_→(문장 전체) 둘 다 계산해
- 진단용으로 ②도 같은 방식으로 채점해

**관문**: 두 조건을 모두 만족해야 통과야.
- T̂_→(π_→ 최대 표제어)가 w_a의 표제어와 같아
- A_→ ≥ 0.00033 (파일럿 1에서 정한 값)

**점수**: log F_→ + S_←. 여기서 S_← = −log π_←(w_p)야. 왼쪽 문맥만 보고 w_p를 만났을 때의 놀람이지. 지금 코드가 다른 값을 쓰고 있으면 이 정의로 맞추고, 바꾼 사실을 기록해.

### 조건별 고르기

P1~P4는 모두 같은 규칙 통과 후보 집합에서 골라.

| 조건 | 고르는 방식 | v1에서 바뀐 점 |
|---|---|---|
| P1 | 고정 시드로 무작위 1개 | 후보 집합이 규칙 통과 후보로 한정 |
| P2 | 관문 통과 후보 중 점수 1위. 통과 후보가 없으면 점수 1위를 고르고 `gate_fail` 표시 | S_← 정의 명시 |
| P3 | 같은 생성기에게 후보 10개를 보여 주고 가장 웃긴 것을 고르게 함 | 보여 주는 순서를 고정 시드로 섞음 |
| P4 (탐색) | He S_ratio 1위. 동점은 고정 시드 무작위 | 후보가 모두 −1이면 `undefined`로 두고 집계에서 n을 따로 보고 |

### 기준선

- **B1**: v1의 단일 프롬프트를 그대로 써서 1회 생성해. "프롬프트 하나로 시키는 방식"의 기준선이야. 규칙 검사는 최종 규칙 검사와 같아.
- **B0**: 쌍 없이 "말장난 하나"를 요청하고, 모델이 `pun_word`와 `alt_word`를 직접 적게 해. 추가 규칙:
  - **쌍 유효성**: 두 단어가 모두 CMUdict에 있고, 음소 편집 거리가 2 이하이고, 서로 다른 표제어여야 해. 아니면 실패야.
  - **잘린 출력**: 실패로 쳐.
  - **재탕**: 걸러내지 않아. 칸 사이 중복률과 infini-gram 최장 일치 길이를 따로 보고해.

## 7. LLM 판정기 (탐색 지표)

판정 모델은 Qwen2.5-7B-Instruct야. 생성기와 다른 계열을 쓰는 거야.

**성공 판정** (`judge_success.txt`):
- 답이 w_p와 같은 표제어면 실패로 쳐.
- 답이 w_a와 같은 표제어면 성공이야.
- 이어서 "Is this a working pun? Answer yes or no."를 물어 (`judge_works.txt`).

**웃김 비교**: 두 순서로 모두 물어. 두 번 다 같은 쪽을 고르면 그쪽의 승리, 엇갈리면 무승부야.

## 8. 파일럿 2

### 구성
- **쌍**: 새 쌍 10개 × 형식 2개 = 20칸.
  - SemEval 쌍, 파일럿 1 쌍, 프롬프트 예시 쌍(bagel/beagle, bread/bed)과 겹치면 안 돼. 겹치는지 코드로 확인해.
  - 파일럿 1과 파일럿 2의 쌍은 모두 본 실행 40쌍에서 빼.
- **생성기**: 아래 둘을 같은 설정으로 돌려. HF id는 실행 전에 확인해.
  - OLMo-2-7B-Instruct (`allenai/OLMo-2-1124-7B-Instruct`)
  - OLMo-2-32B-Instruct (`allenai/OLMo-2-0325-32B-Instruct`)
  - 32B를 4비트로 돌리면 그 사실을 기록해. 본 실행도 같은 설정으로 돌려야 해.
- **판정기·청자 모델**: v1과 같아.
- **사람 평가**: 하지 않아.

### 통과 기준 (실행 전에 고정)

모델별로 판단해.

| 기준 | 내용 |
|---|---|
| C1 채우기 | 모든 칸에서 S1 30회 안에 규칙 통과 후보 10개를 채움 |
| C2 관문 통과 존재 | 칸의 50% 이상에서 관문 통과 후보가 1개 이상 |
| C3 고를 여지 | 후보 10개가 모두 관문을 통과하는 칸이 50% 미만 (다 통과하면 P2와 P1의 차이가 생길 수 없음) |
| C4 판정기 확인 | 규칙 통과 후보 전체의 판정기 성공률 ≥ 0.20 (파일럿 1의 P1은 0.05, 사람 말장난은 0.50) |

**결정 규칙**:
1. 7B가 C1~C4를 모두 넘으면 7B를 본 실행 생성기로 정해.
2. 7B가 못 넘고 32B가 넘으면 32B로 정해.
3. 둘 다 못 넘으면 prereg-e5 태그를 달지 않아. 실패를 기록하고 설계로 돌아가(E6 후보: 활성 조종, 청자 디코딩 조종).

통과 기준에는 가설(H5a~H5c)과 겹치는 비교를 넣지 않았어. P2와 P1의 비교는 본 실행에서만 해.

### 파일럿 2 보고서에 넣을 것

- 모델 × 형식별로 단계마다 실패율
  - S1: 모양, w_a 위치, 횟수
  - S3: 끝 보존, 수정 폭, w_a 누출
  - 최종 규칙 검사
- 칸당 S1 호출 수의 분포
- 관문 통과율
- **진단 D1**: 같은 후보의 ②와 ③에서 A_→를 짝지어 비교해. S3가 실제로 A_→를 올리는지 보는 거야.
- **진단 D2**: 관문 통과 후보와 실패 후보 사이의 판정기 성공률 차이 (A가 가짜 신호인지 점검)
- `topic_link` 분포, 힌트 단어 사용률
- 모델마다 점수 상위 3개와 하위 3개의 예시
- C1~C4 판정표

## 9. 구현 메모

### 기록 (JSONL)

- `attempts.jsonl`: 시도마다 한 줄. 내용은 cell_id, model, seed, ①, S1 검사 결과와 실패 이유, ②, protected_suffix, ③, S3 검사 결과와 재시도 여부, 최종 규칙 결과.
- `candidates.jsonl`: 규칙 통과 후보마다 한 줄. ②·③ 각각의 π_← 상위 5개, π_→ 상위 5개, T̂_→, A_→, F_→, S_←, L, 관문 통과 여부, topic_link를 넣어.
- `selections.jsonl`: 칸 × 조건마다 한 줄. 고른 후보, `gate_fail`, `underfilled`, `undefined` 표시.
- `judge.jsonl`: 판정 요청과 응답 원문.

### 재현성

- 프롬프트 파일마다 SHA-256을 PREREG에 적어.
- 모델 id, 리비전, 양자화 여부, 디코딩 설정, 시드 규칙도 적어.

### 단위 테스트

1. S2: `Bed.` → `Bread.`, `a apple` 같은 관사 교정, 구두점이 붙은 단어 치환
2. S1 검사: w_a가 3회 나오거나 굴절형(`beds`)이거나 위치가 틀린 경우 실패
3. S3 검사: 끝이 바뀌면 실패, 수정 0개나 5개 이상이면 실패, w_a 누출이면 실패
4. 최종 검사: 중복 정규화, 잘린 출력
5. B0 쌍 유효성: `elevator/evelator`(사전에 없음), `sack/days`(거리 초과)가 실패
6. 고르기: 같은 시드면 P1·P4 동점 처리 결과가 같아야 해
7. 판정기: w_p를 그대로 답하면 실패로 처리
