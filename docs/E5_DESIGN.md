# 생성 파이프라인 실험 설계 (E5)

Nov 12, 2026 · @shijun

역할을 나눈 파이프라인(쌍은 발음 모듈, 문장은 LLM, 거르기는 A)이 LLM 혼자 쓴 말장난보다 **말장난 성립률과 웃김을 모두 높이는지** 검증해. 영어로 먼저 하고, 구조가 검증되면 한국어로 옮겨.

## 목표와 가설

**답할 질문**

1. 발음이 비슷한 쌍을 파이프라인이 주면, LLM이 스스로 쌍을 고를 때보다 말장난이 더 자주 성립하는가?
2. 같은 후보들 중에서 A로 고른 것이 무작위로 고른 것보다 더 성립하고 더 웃긴가?
3. A가 LLM의 자기 판정보다 나은 필터인가?
4. 형식(수수께끼형, 한 줄 상황형, Tom Swifty)에 따라 웃김이 달라지는가?

**가설 (실험 전에 PREREG에 등록)**

- **H5a 쌍 제공**: 성립률(P1) > 성립률(B0)
- **H5b A 필터 — 성립**: 성립률(P2) > 성립률(P1)
- **H5c A 필터 — 웃김**: 웃김(P2) > 웃김(P1)
- **H5d A vs LLM 판정** (탐색): P2와 P3의 성립률·웃김 비교
- **H5e 형식** (탐색): 웃김은 한 줄 상황형 ≥ 수수께끼형 > Tom Swifty

조건 이름(B0, P1\~P3)은 아래 실험 조건 절에 정의해. 현재 근거로 보면 H5b는 가능성이 높고(A는 판별에 강했어), H5c는 불확실해(웃김 예측에서 A만의 몸은 경계선이었어).

## 파이프라인 구성

LLM이 약한 일(소리가 비슷한 단어 찾기)은 발음 모듈이, 강한 일(뜻과 상황 쓰기)은 LLM이, 판정은 A가 맡아.

1. **쌍 선택**: 쌍 목록에서 (w\_p, w\_a)와 각각의 뜻(WordNet 첫 뜻풀이)을 가져와.
2. **형식 틀**: 수수께끼형 / 한 줄 상황형 / Tom Swifty(대조군) 중 하나를 골라.
3. **연결 단어** (한 줄 상황형만): w\_p를 받치는 주제어를 word2vec 이웃에서 5개 골라 힌트로 줘. He의 전역 문맥 원리를 따른 거야.
4. **LLM 생성**: 한 번에 후보 10개를 JSON으로 받아. 항목마다 `text`, `pun_word`(w\_p가 문장에 쓰인 형태), `format`을 넣게 해. 프롬프트에 "w\_a는 문장에 쓰지 말 것"을 명시해(PunEval의 게으른 패턴 방지).
5. **규칙 검사**: w\_p 포함, w\_a 미포함(표제어 기준), 40단어 이하, 형식 일치. 탈락한 후보의 수도 기록해.
6. **A 채점**: Pythia-1.4B(베이스)로 π\_←, π\_→를 계산해. 후보·γ·표제어 합 규칙은 PREREG와 같아.
7. **고르기**: 관문을 통과한 후보 중 점수 1위를 골라.
   - 관문: T̂\_→가 w\_a의 표제어와 같고, A\_→가 dev에서 정한 문턱 이상이어야 해(E2a에서 오타형을 걸러낸 기준).
   - 점수: log F\_→ + S\_←. 가중치는 1:1로 고정해. 웃김 점수로 맞추면 생성물 평가와 정보가 섞여.
   - 관문을 통과한 후보가 없으면 점수 1위를 고르고 "관문 실패"로 표시해.

**생성 모델**: 재현성을 위해 공개 지시 튜닝 모델 하나(예: OLMo 2 7B Instruct)를 주 생성기로 쓰고, 가능하면 상용 모델 하나를 보조로 써. 온도는 0.9로 고정해. 생성기는 지시 튜닝 모델이어도 돼. 점수를 매기는 A만 베이스 모델이면 돼.

## 비교 조건과 단어 쌍 표본

### 조건

| 조건 | 입력 | 고르는 방식 | 확인하는 것 |
| --- | --- | --- | --- |
| B0 | "말장난 하나 써줘"만 줌 | 첫 출력 | LLM 혼자의 실력 |
| B1 | 쌍 + 뜻 | 1회 생성 | 쌍을 주는 효과 |
| P1 | 쌍 + 뜻 + 형식 틀 (+ 연결 단어) | 후보 10개 중 무작위 1개 | 틀의 효과 (H5a) |
| P2 | P1과 같음 | A 관문 + 점수 1위 | A 필터의 효과 (H5b, H5c) |
| P3 | P1과 같음 | 같은 LLM이 10개 중 가장 웃긴 것을 고름 | A 대신 LLM 자체 판정 (H5d) |
| P4 (선택) | P1과 같음 | He의 S\_ratio 1위 | 기존 점수와 비교 |

P1\~P4는 **같은 후보 10개**에서 고르기만 달리 해. 그래야 고르는 방식의 효과만 남아. B0는 쌍을 정할 수 없으니 성공률 비교에서만 써.

### 단어 쌍 표본

- **출처**: SemEval에 나온 쌍은 빼. LLM이 외운 농담을 그대로 꺼내면 생성 능력을 잴 수 없어.
- **쌍 목록 만들기**: CMUdict에서 빈도 상위 2만 단어를 대상으로 음소 편집 거리 1\~2인 쌍을 뽑아. 그다음 word2vec 코사인 0.3 미만(뜻이 멀다), 두 단어 모두 명사·동사·형용사인 쌍만 남겨.
- **크기**: 무작위 40쌍. 형식은 수수께끼형과 한 줄 상황형 두 가지로 해서 40 × 2 = 80칸이야.
- **대조군**: Tom Swifty 형식으로 10쌍을 따로 만들어. 장르 효과(1단계에서 웃김 ρ −0.43)를 생성 쪽에서도 확인하는 용도야.
- **상한선**: SemEval 사람 말장난 40개를 같은 평가에 섞어. 생성물이 사람 수준에 얼마나 가까운지 보는 기준이야.
- **오염 검사**: 생성물을 infini-gram으로 조회해 8-gram 이상 겹치는 문장은 표시하고, 분석에서 넣은 버전과 뺀 버전을 모두 보고해.

## 평가

### 사람 평가 1: 성공 여부

평가자에게 문장과 말장난 단어(w\_p)를 보여주고 "이 단어가 어떤 다른 단어처럼 들리나요?"라고 물어. 자유 응답이 w\_a(표제어 기준)와 맞으면 성공이야. 이 과제는 A가 재는 것(청자가 w\_a를 복원하는가)과 같은 구조라서, A의 타당도도 함께 확인할 수 있어. 응답 뒤에 "말장난으로 성립하나요?"(예/아니오)를 하나 더 물어.

### 사람 평가 2: 웃김

같은 쌍·형식 안에서 조건끼리 두 개씩 비교해("어느 쪽이 더 웃긴가"). UKP 데이터와 같은 방식이야. 비교 한 건당 평가자 3명, 점수는 Bradley–Terry로 매겨. 한 칸에 조건 5개(B1, P1, P2, P3, 사람)면 비교 10건이야.

### 자동 지표

- 규칙 통과율, A 관문 통과율 (조건별)
- 새로움: 학습 코퍼스와의 최장 일치 n-gram (infini-gram)
- 다양성: 같은 쌍의 후보 10개 사이 distinct-2, 문장 템플릿 반복률
- LLM 판정: 다른 계열 LLM에게 성공 여부와 웃김을 같은 질문으로 물어. 사람 평가와 맞춰 보는 탐색용 지표야(H5d).

### 평가자

영어 말장난은 원어민이 판정해야 해. 선택지는 세 가지야.

1. **Prolific 소액 실험**: 80칸 × (성공 5문항 + 비교 10건)을 평가자 3명이 보면 대략 4,000건이야. 건당 10초면 11시간 분량이라 몇십만 원 규모야.
2. **영어 능숙 지인**: 비용은 없지만 원어민이 아니면 발음 유사성 판단이 흔들려. 이해도 확인 문항으로 거르고, 결과를 파일럿으로만 보고해.
3. **한국어로 미루기**: 영어는 자동 지표까지만 하고, 사람 평가는 한국어 파이프라인에서 해. 평가자 모집이 가장 쉬워.

어떤 선택지든 평가자에게 조건 이름을 숨기고, 순서를 섞어.

## 분석, 진행 순서, 위험

### 분석

- **H5a, H5b**: 성공률을 쌍 단위로 짝지어 비교해(P1 vs B1, P2 vs P1). 쌍을 묶음 단위로 재표집하는 부트스트랩 95% 구간을 써.
- **H5c**: Bradley–Terry 점수 차이(P2 − P1)를 같은 부트스트랩으로 검정해.
- **H5d, H5e**: 탐색 분석이야. A 점수, LLM 판정, 사람 점수 사이의 순위 상관을 보고, 형식별로 나눠 봐.
- 실행 전에 조건, 표본, 관문 문턱, 검정 방법을 PREREG에 적고 태그(prereg-e5)를 달아.

### 진행 순서

1. **파일럿** (10쌍, 자동 지표만): 규칙 통과율과 실패 유형을 확인해.
2. **프롬프트·관문 수정**: 파일럿 결과로 한 번만 고치고 고정해.
3. **본 실행**: 40쌍 × 2형식 + Tom Swifty 10쌍.
4. **사람 평가**: 위 세 선택지 중 하나로.
5. **한국어 확장**: 수수께끼형 아재개그부터 시작해. 발음은 g2pK, 청자 모델은 한국어 베이스 모델로 바꿔.

### 위험과 대응

| 위험 | 대응 |
| --- | --- |
| LLM이 유명 말장난을 베낌 | SemEval 쌍 제외 + infini-gram 검사 |
| A를 속이는 출력 (w\_a가 너무 뻔해 웃기지 않음) | 웃김을 따로 평가하고, P2가 성공은 높고 웃김은 낮은지 확인 |
| 후보가 관문을 거의 통과하지 못함 | 파일럿에서 통과율 확인, "관문 실패" 비율 보고 |
| 평가 비용 | 한국어로 미루는 선택지, 칸 수 축소 |
| 형식 교란 (Tom Swifty) | 형식을 조건으로 두고 형식 안에서만 비교 |
| 생성 모델이 바뀌면 결과가 달라짐 | 공개 모델을 주 생성기로, 버전과 시드 기록 |
