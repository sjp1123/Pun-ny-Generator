# E6 설계: 채점기 검증과 생성 v3

E5 본 실행(PREREG_E5 7.2)에서 생성 방식이 막힌 곳을 고치는 다음 실험의 설계다. 두 부분으로 나눈다.

1. **채점기**: 연구자 판단과 맞는 자동 채점기를 만들고 검증한다. 생성기를 고르거나 학습할 때 쓸 신호다.
2. **생성 v3**: 두 단어를 함께 보는 계획 단계를 넣고, 앞부분을 다시 쓰게 한다.

생성기 학습(DPO)은 1과 2가 끝난 뒤 따로 설계한다(7절).

---

## 0. E5에서 본 문제 (탐색, `experiments/e5v2_explore_listener.py`)

| 문제 | 근거 |
|---|---|
| 실패한 P 문장 86개 중 43%는 w_p가 문장에 맞지 않는다(오타처럼 읽힘). 40%는 두 뜻이 다 되지만 말장난이 아니다 | 연구자 (a)·(b)·(c) |
| 어느 LLM 단계도 두 단어를 함께 보지 않는다. S1은 w_a 문장을 쓰고, S3는 w_p 쪽 단어를 1~4개 끼운다. 농담을 짜는 단계가 없다 | 2절 설계 |
| P2 점수(log F_→ + S_←)는 w_a가 떠오르는지와 맞고(AUC 0.78) w_p가 맞는지와는 반대로 간다(0.38). S_←가 w_p의 놀람을 보상하기 때문이다 | 연구자 (a)·(b), 268문장 |
| phi-4 `works_pair`는 연구자가 w_p가 맞지 않는다고 본 문장의 57%에 yes를 준다. P 문장에서 연구자 (c)와의 균형 정확도는 0.630이다 | 연구자 (c), 268문장 |
| 현재 점수는 phi-4 성립을 칸 안에서 맞히지만(AUC 0.646) 연구자 (c)는 맞히지 못한다(0.510). log F_→만 쓰면 0.629, log F_→ − S_←는 0.631이다 | 탐색 계산 |
| 뜻풀이(WordNet)를 문장에 그대로 옮긴 후보가 있다(P 문장의 3%) | 4단어 이상 일치 |

따라서 phi-4 `works_pair`만으로는 고르기나 학습의 신호로 쓸 수 없다. 채점기를 먼저 고친다.

## 1. 데이터 나누기

| 묶음 | 쌍 | 쓰임 |
|---|---|---|
| 개발 | E5 본 실행 40쌍(연구자 라벨 508문장), E5 파일럿 쌍 | 채점기 개발과 검증, 생성 v3 설계 |
| 파일럿 | 새 10쌍 | 생성 v3 파일럿 |
| 시험 | 새 40쌍 | E6 본 실행. 본 실행 전에는 어떤 문장도 만들지 않는다 |
| 학습 | 새 쌍 수백 개 | 7절에서 정한다 |

- 새 쌍은 `e5/pairs_v4.csv`(2,856쌍)에서 E5가 쓴 단어(파일럿 1~7, 본 실행, 프롬프트 예시)를 뺀 나머지에서 뽑는다.
- 뽑는 규칙은 `e5v4_pairs.py`와 같다. 묶음 사이에 같은 단어가 없다. 시드는 `stable_seed("e6", "samples")`다.
- 층 비율은 d0·sub·indel = 파일럿 0·5·5, 시험 0·20·20이다. d0(발음이 같은 쌍)은 `pairs_v4`에 37쌍뿐이고 E5가 거의 다 썼다.
  남은 2쌍도 품사 방향 규칙을 통과하지 못했다(2026-11-27 확인). E5에서 d0은 가장 쉬운 층이었으므로(연구자 성립 0.78, sub 0.70,
  indel 0.55) E6의 성립 값은 E5보다 낮게 나올 수 있다. E6의 비교는 같은 쌍 안에서 하므로 층 구성의 차이는 비교에 영향을 주지 않는다.
- 출력은 `e6/samples.json`이다. 커밋해서 고정한다.

## 2. 채점기

### 2.1 LLM 판정 세 문항

연구자 평가지의 세 문항을 판정기에 따로 묻는다. 평가지처럼 쌍과 두 단어의 짧은 뜻풀이를 함께 보인다.

| 문항 | 프롬프트 요지 | 파일 |
|---|---|---|
| (a) | "{w_p}"를 원래 뜻({g_p})으로 읽을 때 이 문장이 말이 되는가 | `e6/prompts/judge_a.txt` |
| (b) | "{w_p}" 자리를 "{w_a}"({g_a})로 바꿔 읽어도 이 문장이 말이 되는가 | `e6/prompts/judge_b.txt` |
| (c) | 두 뜻이 함께 떠오르는 성공한 말장난인가 (He et al.과 같은 질문) | `e6/prompts/judge_c.txt` |

- 판정기 후보는 GPU PC에 이미 받아 둔 모델만 쓴다: `microsoft/phi-4`(NF4), `Qwen/Qwen2.5-14B-Instruct`(NF4).
  OLMo-2-32B는 생성기와 같은 모델이라 쓰지 않는다.
- 온도 0, 문장마다 문항당 1회. 답은 첫 단어 yes/no로 읽는다.
- 합성 규칙 후보: (c)만, (a) ∧ (c), (a) ∧ (b) ∧ (c).

### 2.2 청자 점수 고치기

현재 점수에서 S_←(w_p의 놀람)를 보상하지 않게 바꾼다. 다음 후보를 비교한다. 모두 이미 있는 `scores.csv` 값으로 계산한다.

| 후보 | 식 |
|---|---|
| L0 (현재) | log F_→ + S_← |
| L1 | log F_→ |
| L2 | log F_→ − S_← |
| L3 | 칸 안 표준화 z(log F_→)와 z(−S_←)의 최솟값 (두 쪽이 모두 받쳐져야 높다) |

관문(T̂_→ = w_a, A_→ ≥ 문턱)은 그대로 둔다. 관문 통과 후보의 phi-4 성립은 0.69, 탈락 후보는 0.51이었다.

### 2.3 최종 채점기

`채점 = LLM 합성 규칙 판정 + 청자 점수`. 판정이 yes인 후보 중 청자 점수가 높은 후보를 고른다.
LLM 판정만 쓰는 것, 청자 점수만 쓰는 것과 함께 비교한다.

### 2.4 검증

- **라벨**: 연구자의 E5 라벨. 칸 묶음 428문장(P, B1, H)과 B0 71문장(판정할 수 있는 것)이다.
- **나누기**: E5 본 실행 40쌍을 `stable_seed("e6", "judge_split")`로 20쌍씩 나눈다.
  개발 절반에서 판정기, 프롬프트 문구, 합성 규칙, 청자 점수를 고르고, 확인 절반에서 한 번만 잰다.
- **기준 (확인 절반, 미리 고정)**: P와 B1 문장에서 연구자 (c)와의 균형 정확도가 다음을 모두 넘으면 통과다.
  1. 0.70 이상
  2. 같은 문장에서 phi-4 `works_pair`보다 0.05 이상 높음
  3. 연구자가 (a) 아니오로 본 문장의 yes 비율이 0.35 이하
- **고르기 모의**: E5 후보 791개에서 채점기로 칸마다 하나를 골랐을 때의 성립을 무작위(0.612), 최선(0.925)과 함께 보고한다.
  성립은 연구자 라벨이 있는 문장에 한해 연구자 (c)로, 없으면 phi-4로 잰다. 두 값을 따로 적는다.
- 확인 절반에서 기준을 넘지 못하면 판정기를 더 고치지 않는다. 가장 나은 조합을 쓰고, 한계로 적는다.
- 청자 점수 L0~L3은 나누기 전(2026-11-27)에 40쌍 전체에서 탐색 계산으로 한 번 보았다(0절의 AUC). 따라서 청자 점수에 대해서는
  확인 절반이 완전히 새 자료가 아니다. LLM 판정은 나누기 전에 돌리지 않았다.
- 구현: `experiments/e6_scorer.py` (`split`, `inputs`, `judge`, `dev`, `confirm`). 나누기는 `e6/judge_split.json`,
  판정할 문장은 `e6/judge_inputs.csv`, 프롬프트는 `e6/prompts/judge_a.txt`, `judge_b.txt`, `judge_c1.txt`(c0은 `works_pair.txt`).
  고르는 규칙은 스크립트 머리말에 적었다.

## 3. 생성 v3

v2(S1 → S2 → S3)의 뼈대를 두고 두 단계를 바꾼다.

```
입력: (w_p, g_p), (w_a, g_a), 형식 f
  │
  ├─ S0  장면 정하기     [LLM, 두 단어 앎]  → 두 뜻이 함께 어울리는 상황 한 줄과 주제 단어 2~3개
  ├─ S1  w_a 문장 쓰기   [LLM, w_a와 장면]  → 장면 안에서 w_a로 끝나는 평범한 문장
  ├─ S2  바꿔 끼우기     [코드]             → w_a를 w_p로 바꿈 (v2와 같음)
  ├─ S3' 앞부분 다시 쓰기 [LLM, w_p와 장면]  → 끝 보존, w_p를 원래 뜻으로 읽어도 말이 되게 앞부분을 고쳐 씀
  ├─ 최종 규칙 검사       [코드]
  └─ 채점과 고르기
```

- **S0**: 예시 bagel/beagle → "빵집 주인이 보호소에서 강아지를 데려온다". 출력은 JSON 한 줄(`scene`, `topic_words`)이다.
  S0 출력은 문장에 들어가지 않는다. S1·S3'에 장면으로만 준다.
- **S1**: v2 S1 프롬프트에 장면을 더한다. 검사 규칙은 v2와 같다.
- **S3'**: v2의 "1~4단어 끼우기" 대신 끝(보호 구간)을 뺀 앞부분 전체를 다시 쓰게 한다. 수정 폭 상한을 없애고, 끝 보존·w_p 1회·w_a 없음
  검사는 그대로 둔다.
- **뜻풀이 베끼기 검사**: 최종 문장이 g_p나 g_a와 4단어 이상 연속으로 겹치면 실패로 친다.
- **후보 수**: 칸당 규칙 통과 10개(v2와 같음).
- 프롬프트: `e6/prompts/s0_*.txt`, `s1_*.txt`, `s3_*.txt`.

## 4. 파일럿 (새 10쌍 × 2형식 = 20칸)

- 같은 20칸에서 v2와 v3를 모두 생성한다. 두 방식의 후보를 2절 채점기와 phi-4로 잰다.
- **보는 값**: 무작위 1개의 채점기 성립, 칸별 최선, (a) 판정 아니오 비율, 문장 틀 반복률, 뜻풀이 베끼기 비율, 규칙 통과율, 생성 호출 수.
- **통과 기준 (실행 전에 고정)**: v3 무작위 1개의 채점기 성립이 v2보다 0.10 이상 높고, (a) 아니오 비율이 v2보다 낮다.
- 파일럿은 최대 3회. 고칠 때마다 무엇을 바꿨는지 이 문서에 적는다. 3회 안에 통과하지 못하면 가장 나은 판을 E6에 쓰고 한계로 적는다.

## 5. E6 본 실행 (개요, 사전등록은 `PREREG_E6.md`로 따로 쓴다)

| 조건 | 내용 |
|---|---|
| V2-R | v2 생성, 무작위 1개 (E5의 P1과 같은 방식) |
| V3-R | v3 생성, 무작위 1개 |
| V3-S | v3 생성, 2절 채점기로 고름 |
| B1 | 단일 프롬프트 1회 (E5와 같음) |
| H | 사람 말장난 (상한 기준) |
| (학습 조건) | 7절을 설계한 뒤 더한다 |

- 가설 후보: V3-R − V2-R(생성 구조의 효과), V3-S − V3-R(고르기의 효과).
- 주 측정은 사전등록 때 정한다. 후보는 연구자 블라인드 평가의 (c)와 2절에서 검증한 채점기다.
  - 채점기를 주 측정으로 쓰려면 2.4 기준을 통과해야 한다.
  - V3-S는 채점기로 고른 조건이라, 같은 채점기로 V3-S − V3-R을 재면 V3-S에 유리하다. 이 비교의 주 측정은 연구자 평가로 한다.
- B0 쌍 규칙은 처음부터 3.2 규칙(`b0_pair_reasons`)을 쓴다(PREREG_E5 7.2).
- 오염 조회, distinct-2, 문장 틀 반복률은 E5와 같다.

## 6. 구현 순서

1. `e6/samples.json` 뽑기 (CPU)
2. 청자 점수 후보 L0~L3 계산과 개발 절반 비교 (CPU, 이미 있는 값)
3. 판정 프롬프트 세 개와 `experiments/e6_judge.py` 작성 → GPU에서 E5 라벨 문장 499개 × 2판정기 × 3문항 판정
4. 개발 절반에서 조합 고르기 → 확인 절반 한 번 재기 → 이 문서에 결과 적기
5. 생성 v3 프롬프트와 `experiments/e6_generate.py` 작성 → GPU에서 파일럿
6. 파일럿 통과 뒤 `PREREG_E6.md` 작성, 태그, 본 실행

## 7. 생성기 학습 (나중에 설계)

2절의 채점기와 3절의 v3가 정해진 뒤 설계한다. 정할 것: 학습할 모델 크기(GPU 메모리에 따라 다름), 학습용 쌍 수,
좋은 문장과 나쁜 문장을 짝짓는 규칙, 채점기에 맞춘 꼼수를 막는 방법, 학습 조건을 E6에 넣는 방식.
