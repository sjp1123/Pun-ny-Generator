## 실험 1. 분석 규칙 고정 (사전 등록)

목표는 1.4B 결과를 보기 전에 분석에서 고를 수 있는 것을 전부 고정하는 거야. **결과를 보고 규칙을 고르는 일을 막는 게 목적이야.**

### 1-A 분할 고정

- `splits/dev_ids.txt`, `splits/test_ids.txt`를 만들고 각 파일의 SHA-256을 `PREREG.md`에 적어.
- 확인 검정(H1a\~c, H3, H4)은 **test 중 숨은 단어가 한 단어인 항목만**으로 해.
- γ, 거리 구간 가중치, Kao의 z·r 같은 파라미터는 dev 전체에서 맞추고, test에는 고정값을 적용해. 기존의 "1,074개 5겹 교차검증"을 대신해.
- E3 회귀는 기존처럼 test 안에서 10겹 교차검증으로 해.

### 1-B 숨은 단어 채점: 표제어 합

SemEval의 alter\_word는 WordNet 의미 주석에서 왔어서 표제어로 적혀 있어. 듣는 사람이 떠올리는 건 활용형(arms, sold)이니까, "그 낱말의 어느 활용형이든 떠올리면 복원"으로 정의해. **최댓값이 아니라 합을 쓰는 게 핵심이야.** 최댓값은 결과를 좋게 보이는 쪽으로 치우쳐.

```latex
M(w_a) = \{\, T \in \mathcal{C},\ T \neq w_p \;:\; \mathrm{lemma}(T) = \mathrm{lemma}(w_a) \,\}, \qquad \pi_{\mathrm{lex}}(w_a) = \sum_{T \in M(w_a)} \pi(T)
```

- 표제어 도구 하나를 정해서 버전까지 기록해(예: LemmInflect 또는 spaCy).
- F, A, L을 계산할 때 π(w\_a) 대신 π\_lex(w\_a)를 써.
- E1에서는 후보를 표제어별로 묶어 확률을 합하고, 가장 큰 묶음이 lemma(w\_a)면 정답으로 채점해. MRR도 묶음 순위로 계산해.
- lemma(w\_p) = lemma(w\_a)인 항목은 제외하고 개수를 보고해.
- **손 점검**: strict와 표제어 합의 판정이 갈리는 항목 20개를 dev에서 무작위로 뽑아 직접 확인해. 도구 오류(예: 명사 saw를 동사 see로 바꿈)가 2개를 넘으면 도구를 바꾸거나 예외 목록을 만들어.
- 보조 보고: strict, 표제어 최댓값(160M 보고서와 이어 보기 위한 것)

### 1-C H1c 직접 검정

기존 판정("Δρ(pair, γ = 0)의 신뢰구간이 0을 포함하면 지지")은 "차이를 못 찾았다"를 "효과가 사라졌다"로 읽는 오류야. 두 조건의 차이를 직접 검정해.

```latex
\delta = \rho(\mathrm{M1}_{\mathrm{full}}) - \rho(\mathrm{M1}_{\mathrm{pair0}})
```

- M1\_full: 기준선 묶음 + 전체 후보·γ로 계산한 A 지표
- M1\_pair0: 기준선 묶음 + 후보 {w\_p, w\_a}·γ = 0으로 계산한 같은 지표
- 기준선 묶음 M0는 양쪽에 같아서 차이에서 빠져.
- 절차: 두 모델의 10겹 교차검증 예측값을 한 번 계산해 두고, 항목을 복원 추출해서(두 모델에 같은 표본) δ의 분포를 만들어.
- 판정: 95% 신뢰구간 하한이 0보다 크면 지지야. "전체 후보 정규화와 발음 항이 He의 두 후보 방식보다 웃김을 더 잘 설명한다"는 뜻이 돼.
- 160M으로는 구현이 동작하는지만 확인해.

## 실험 2. 웃김 점수의 잡음 상한

사람 웃김 점수가 얼마나 믿을 만한지 재서, **어떤 예측 점수든 도달할 수 있는 상관의 상한**을 구해. 지금은 ρ 0.30이 높은지 낮은지 판단할 기준이 없어. 언어 모델이 필요 없는 실험이라 몇 분이면 끝나.

**데이터** (`data/pl-humor-full/results.tsv`, 직접 확인한 값)

| 항목 | 값 |
| --- | --- |
| 열 | Worker ID, Answer, Text A, Text B |
| 판단 수 | 141,050 (서로 다른 쌍 28,210개 × 5명) |
| 평가자 | 1,059명 |
| 문장별 비교 횟수 | 4,030개 모두 70번 |
| 응답 | A 58,986 · B 54,652 · X(우열 없음) 27,412 (19%) |

**절차**

1. **점수 계산법**: 주 방법은 Bradley–Terry(`choix` 라이브러리, 정규화 α = 0.01)야. X는 양쪽에 0.5승씩 줘. 보조 방법은 승률 점수 (승 + 0.5 × X) / 등장 횟수야.
2. **점수 검증**: 판단 전체로 계산한 점수와 `item_scores.txt`의 스피어만 상관을 보고해. 0.9 미만이면 원 점수의 계산법을 먼저 찾아서 맞춰.
3. **반분**: 평가자 1,059명을 무작위로 반씩 나눠 각 반쪽의 판단만으로 점수를 따로 계산해. 점수 계산에는 4,030개 전부를 쓰고, 두 점수의 스피어만 상관 r\_half는 말장난 집합 안에서만 구해. 200번 반복해.
4. **보정**: 반쪽 데이터의 신뢰도를 전체 데이터 기준으로 바꿔(스피어만-브라운), 그 제곱근을 상한으로 써.

```latex
r_{\mathrm{full}} = \frac{2\, r_{\mathrm{half}}}{1 + r_{\mathrm{half}}}, \qquad \rho_{\max} \approx \sqrt{r_{\mathrm{full}}}
```

5. **보조 분할**: 평가자 대신 판단 단위로도 나눠 봐. 쌍마다 5명 중 2명과 3명으로 나누고, 어느 쪽이 3명을 가져갈지는 무작위로 정해.

**산출물**: 아래 표 하나야.

| 집합 | 분할 방식 | r\_half 평균 (95% 구간) | r\_full | ρ\_max |
| --- | --- | --- | --- | --- |
| 말장난 1,074 | 평가자 |  |  |  |
| 말장난 test | 평가자 |  |  |  |
| 말장난 1,074 | 판단 |  |  |  |
| 전체 4,030 | 평가자 |  |  |  |

**해석 규칙**

- 앞으로 모든 E3 표에 **상대 성능 = 관측 ρ / ρ\_max**를 함께 적어.
- 말장난끼리는 웃김 차이가 작아서, 전체 4,030개보다 신뢰도가 낮게 나오는 게 정상이야. 두 값의 차이도 보고해.
- ρ\_max가 0.4 아래로 나오면, 말장난끼리의 웃김 예측(E3)은 이 데이터로 작은 차이를 가리기 어렵다고 명시해. 이 경우 E2(판별)의 비중을 주장에서 더 키워.

## 실험 3. 읽는 순간 vs 다 읽은 뒤

근거 없이 정한 국소 창(앞뒤 2단어)을, 사람이 문장을 읽는 순서에 맞춘 두 시점으로 바꿔. **어긋남은 왼쪽 문맥만 보고 pun word를 만난 순간의 놀람으로, 해소는 문장 전체를 본 뒤의 F로 재.** 인과 언어 모델의 구조와 그대로 맞고, 임의의 창 크기가 사라져.

### 정의

```latex
P_{\leftarrow}(T) = P_{\mathrm{LM}}(T \mid x_{1:i-1}), \qquad \pi_{\leftarrow}(T) \propto P(\varphi_p \mid T)^{\gamma}\, P_{\leftarrow}(T)
```

- T가 여러 토큰이면 토큰 확률을 고루 곱해(앞 공백 포함). 후보 집합과 γ는 기존과 같아.
- 다 읽은 뒤의 π\_→는 지금의 π\_global 그대로야(이름만 바꿔).

| 지표 | 정의 | 의미 |
| --- | --- | --- |
| S\_← | −log π\_←(w\_p) | 읽는 순간 글자 그대로의 단어에 대한 놀람. 연속값이라 D처럼 1에 붙지 않아 |
| F\_← | π\_←(w\_a) / (1 − π\_←(w\_p)) | 읽는 순간 기대하던 단어가 숨은 단어였나 |
| F\_→, L\_→, A\_→ | 기존 F\_global, L\_global, A\_global | 다 읽은 뒤의 해소 |
| U | KL(π\_→ ‖ π\_←) | 오른쪽 문맥이 해석을 얼마나 바꿨나 (탐색) |

### 알고 있어야 할 데이터 사실

SemEval 이형 말장난 1,098개를 직접 세어 보니, \*\*pun word가 마지막 단어인 문장이 629개(57.3%)\*\*야. 뒤에 단어가 1개인 문장이 216개(19.7%), 2개 110개(10.0%), 3개 이상 143개(13.0%)이고, 왼쪽 문맥이 비어 있는 문장은 9개야.

- 그래서 절반 넘는 문장에서는 π\_←와 π\_→가 거의 같아. 이런 문장에서 이 실험이 바꾸는 건 "포화된 D\_local → 연속값 S\_←"뿐이야.
- U나 "오른쪽 문맥에 의한 갱신" 같은 분석은 뒤에 단어가 2개 이상인 문장(253개, 23%)에서만 의미가 있어. 이 부분집합을 따로 표시해서 분석해.
- 왼쪽 문맥이 비어 있으면 문장 시작 토큰만 두고 계산하고 플래그를 달아.

### dev 점검

**채택 여부를 성능으로 정하지 않아.** 임의의 창을 없애는 건 이론적 이유로 정한 거고, dev는 구현이 맞는지만 확인해.

1. **포화 비교**: D\_local > 0.99인 비율과 D\_← > 0.99인 비율, 그리고 S\_←의 분포(히스토그램)를 보고해.
2. **구현 확인**: 마지막 단어가 pun word인 문장에서 π\_←와 π\_→의 차이가 거의 0인지 확인해. 남는 차이는 문장부호 때문이어야 해.
3. **방향 확인**: He 6유형에서 S\_← 평균을 보고해. pun과 retrieved\_aw\_alter에서 크고, depun과 retrieved\_aw·retrieved\_pw에서 작아야 해.

### 등록할 가설 (1.4B, test)

- **H3a**: M0 + {S\_←, log F\_←, log F\_→, A\_→}의 Δρ가 0보다 크다(95% 신뢰구간 하한 > 0).
- **H3b (비열등)**: ρ(M1\_읽기시점) − ρ(M1\_원안)의 95% 신뢰구간 하한이 −0.02보다 크다. 임의의 창을 없애도 예측력이 떨어지지 않는다는 뜻이야.
- U와 웃김의 관계, 뒤에 단어 2개 이상 부분집합 분석은 탐색으로 표시해.

### 구현 메모

- 왼쪽 문맥 확률은 "왼쪽 문맥 + 후보"를 한 배치로 넣고 후보 토큰 자리의 로그 확률만 더해 구해. 기존 캐시에 문맥 종류 `left`로 추가해.
- 계산량은 기존 전역 채점보다 작아(문장이 짧아서).

## 실험 4. 발음 항 개선과 발음 기여 분리

두 문제를 다뤄. 4-A는 발음 항이 너무 약한 문제(완전 동음에서 발음만 0.854 > 전체 0.570)이고, 4-B는 후보를 발음으로 미리 골라서 **γ가 일할 필요가 없었던 문제**야.

### 4-A 거리 구간 가중치

γ 하나 대신 거리 구간마다 따로 벌점을 줘:

```latex
\log q(T) = \ell(T) - w_{b(d)}, \qquad b(d) \in \{0, 1, 2, 3^{+}\}, \qquad w_0 = 0
```

- d는 w\_p와의 단순 음소 편집 거리야. w\_p 자신과 완전 동음어는 d = 0이야.
- 자유 파라미터는 w\_1, w\_2, w\_3+ 세 개야(범위 \[0, 30\]). 단조 제약 w\_1 ≤ w\_2 ≤ w\_3+를 넣은 버전과 뺼 버전을 둘 다 맞춰.
- 맞추는 목표: dev에서 Σ log π\_→(w\_a 묶음) 최대화(L-BFGS-B). 단일 γ도 같은 목표로 dev에서 다시 맞춰서 비교해.
- 과적합 확인: dev 안에서 5겹 교차검증으로 검증 겹의 로그 우도를 비교해.
- 보고: E1 acc@1(묶음 기준)을 완전 동음과 유사 동음으로 나눠서. **핵심 확인은 완전 동음에서 "발음만"과 "전체"의 차이가 줄어드는지야.**
- H1은 단일 γ 그대로 두고, 구간 가중치는 H4a로 따로 보고해.

### 4-B 후보 합집합: 발음의 기여 분리

지금은 후보를 발음 거리 상위 100개로 뽑어서, γ = 0이어도 발음 정보가 후보 필터로 들어가 있어. 그래서 "γ를 꺼도 결과가 같다"는 "발음이 필요 없다"는 뜻이 아니야. 발음 항이 진짜로 일해야 하는 조건을 만들어서 비교해.

**후보 집합 세 가지**

- C\_phon: 지금 방식(발음 거리 상위 100개 + w\_p)
- C\_LM: 언어 모델이 그 자리에 올 것으로 보는 단어 상위 100개 + w\_p. 어휘 V의 단어를 왼쪽 문맥에서의 첫 토큰 로그 확률로 줄 세우고, 상위 100개만 정확히 다시 채점해.
- C\_union: C\_phon ∪ C\_LM (최대 201개)

**발음 항 세 가지**: 없음(γ = 0), 단일 γ, 구간 가중치(4-A). γ와 가중치는 후보 집합마다 dev에서 따로 맞춰.

**채울 표** (dev 먼저, 동결 후 test). 칸마다 E1 acc@1 / 후보 재현율 / E3 ρ(log F\_→)를 적어.

| 후보 집합 | γ = 0 | 단일 γ | 구간 가중치 |
| --- | --- | --- | --- |
| C\_phon |  |  |  |
| C\_LM |  |  |  |
| C\_union |  |  |  |

**예측과 해석**

- C\_union에서 γ = 0이면 언어 모델이 뜻만 맞고 발음은 무관한 단어를 고를 거야. 그러면 E1이 크게 떨어지고, γ > 0에서 회복돼야 해.
- 그렇게 나오면 결론은 "발음 정보는 필수이고, 지금까지는 후보 필터가 그 일을 대신했다"야.
- C\_union에서도 γ = 0과 γ > 0이 비슷하게 나오면, 그때는 "발음 가중치가 복원에 기여하지 않는다"고 솔직하게 보고해. 이론의 중요한 반증이야.
- C\_LM의 재현율이 낮다면 그 자체가 "언어 모델만으로는 숨은 단어를 떠올리지 못한다"는 증거야.

### 등록할 가설 (1.4B, test)

- **H4**: C\_union에서 E1 acc@1(단일 γ) − acc@1(γ = 0) > 0. 짝지은 부트스트랩 95% 신뢰구간 하한 > 0이면 지지.
- **H4a (탐색)**: C\_phon에서 구간 가중치가 단일 γ보다 E1 acc@1이 높다.

### 계산량

후보가 최대 201개라 기존의 약 2배야. 160M CPU로 충분해. C\_LM을 뽑는 단계는 문장마다 forward 한 번이면 돼.
