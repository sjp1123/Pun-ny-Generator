# 한국어 말장난 생성 (K 계열) 설계 초안

작성 2026-11-17. 영어 E5(세 단계 생성 + 청자 모델로 고르기)를 한국어로 옮기는 계획이다. 아직 초안이고, 끝의 "정해야 할 것"이 정해지면
사전 등록(`PREREG_K.md`)으로 옮긴다.

## 0. 왜 한국어인가, 무엇을 묻는가

- 영어 E5의 가장 큰 약점은 평가였다. 사람 평가는 연구자 한 명이고, 그 평가자가 영어 모국어 화자가 아니다. 한국어에서는 평가자가 모국어 화자다.
- 질문은 E5와 같다: **청자 모델(언어 모델)로 고르면 무작위보다 성립하고 웃긴 말장난을 고르는가?** 그리고 쌍을 주고 단계로 만들면 쌍 없이 만들 때보다 나은가?
- 추가로 묻는 것: 영어에서 만든 틀(발음 거리, 표제어 합 청자, 관문)이 철자와 발음의 관계가 다른 언어에서도 작동하는가?

## 1. 한국어 말장난은 영어와 어떻게 다른가

| 종류 | 예 | 영어 E5 틀로 다룰 수 있나 |
|---|---|---|
| 철자가 다른 같은 소리 (표준 발음이 같음) | 같이 [가치] / 가치, 반듯이 / 반드시, 낫 / 낮 / 낯 [낟] | **예**. 영어의 거리 0 쌍(heir/air)과 같다 |
| 자모 하나 차이 | 사자 / 사장, 공 / 곰 | **예**. 영어의 거리 1 쌍과 같다 |
| 철자도 같은 동음이의어 | 사과(apple / 사죄), 배(배 / 선박 / 복부) | **아니오**. S2에서 바꿀 글자가 없고, 청자 모델의 후보가 같은 문자열이라 A가 정의되지 않는다. 뜻 단위 모형이 필요하다 |
| 어절 경계를 넘는 재분절 | "가장 뜨거운 바다는? 열바다" (열받아) | **아니오**. w_p가 사전에 없는 말이고 두 어절에 걸친다 |
| 외래어 섞기 | "왕이 넘어지면? 킹콩" | **아니오** |

한국어 말장난(아재개그, 넌센스 퀴즈)은 아래 세 종류가 많다. 한글은 소리대로 적는 편이라 같은 소리는 대개 같은 철자다. 그래서 **철자가 다른 같은 소리 쌍은
영어보다 드물 수 있다.** 이것이 이 계획의 첫 번째 위험이고, K1에서 쌍 개수부터 센다.

**1단계 범위(추천)**: 철자가 다른 근접 동음 쌍(거리 0~1)만. E5의 모든 장치가 그대로 쓰이고 영어 결과와 비교할 수 있다. 같은 철자 동음이의어는
2단계(뜻 단위 청자)로 미룬다.

## 2. 영어 E5에서 그대로 가는 것과 새로 만드는 것

| 부분 | 영어 E5 | 한국어 | 비고 |
|---|---|---|---|
| 세 단계 생성 S1 → S2 → S3 | `e5v2_generate.py` | 그대로 | 프롬프트만 한국어로 |
| S2 바꿔 끼우기 | 대소문자, a/an | **조사 이형태**: 받침 유무로 은/는, 이/가, 을/를, 와/과, ㄹ받침 예외 포함 으로/로 | a/an 고치기와 같은 자리 |
| 형식 | 수수께끼, 한 줄 | **넌센스 퀴즈**(Q/A), 한 줄 | 넌센스 퀴즈가 한국어 말장난의 대표 형식이라 잘 맞는다 |
| 발음 | CMUdict + g2p_en → ARPAbet | **g2pK**(표준 발음 규칙 적용, Windows는 g2pkk) → 자모 → IPA | 연음·경음화·비음화 때문에 철자와 소리가 다르다. 단어 단독 발음과 문장 속 발음이 다를 수 있다 |
| 발음 거리 | panphon 자질 편집 거리, 단순 편집 거리 | 같은 panphon(IPA라면 언어와 무관) + 자모 편집 거리 | `phon.py` 재사용 |
| 어휘·빈도 | CMU ∩ wordfreq 상위 2만 | 우리말샘/표준국어대사전 **명사** ∩ 빈도 상위 | wordfreq의 한국어는 MeCab이 필요하다. 국립국어원 빈도 목록도 후보 |
| 형태소·표제어 | spaCy, WordNet 표제어 | **Kiwi**(kiwipiepy, Windows에서 바로 됨) | 표제어 합 청자의 "같은 표제어" 판단 |
| 뜻풀이 | WordNet 흔한 뜻(SemCor) | 우리말샘/표준국어대사전 첫 뜻 + 빈도 | 흔한 뜻을 고르는 기준이 영어만큼 깔끔하지 않다 |
| 뜻 거리 | word2vec GoogleNews cos < 0.3 | fastText 한국어(cc.ko.300) | 문턱은 분포를 보고 다시 정한다 |
| 청자 모델 | Pythia-1.4B | **Polyglot-Ko 1.3B**(EleutherAI, Pythia와 같은 GPT-NeoX 구조, 한국어 위주 학습) | 크기와 구조가 같아 비교가 쉽다. 대안: KORMo 10.8B(학습 자료 공개) |
| 청자 후보 | 발음 상위 100 + w_a | 같음. 단 **조사까지 붙인 어절**로 채점 | 명사만 다루면 조사만 맞춰 바꿔 넣으면 된다 |
| γ, 관문 문턱 | SemEval dev, He 자료 | **한국어 말장난 자료가 없다** → K2에서 만든다 | 가장 큰 공백 |
| 생성기 | OLMo-2 32B NF4 | 파일럿으로 고른다: EXAONE 4.0 32B(연구용 공개 가중치), Qwen 계열 32B 등 | 4비트로 20GB GPU에 올라가야 한다. 라이선스 확인 |
| 판정기 | phi-4 (사람 자료로 검증) | 한국어로 다시 검증해야 한다 | 검증할 한국어 사람 자료가 없으므로 K2의 네 라벨로 한다 |
| 사람 평가 | 연구자 1명(비모국어) | 연구자 1명(**모국어**), 블라인드 | 영어에서 짠 단일 평가자 설계를 그대로 쓴다 |

## 3. 단계별 계획

각 단계 끝에 진행할지를 정하는 기준이 있다(통과 못 하면 범위를 바꾸거나 멈춘다).

### K0 도구 확인 (CPU, 하루)
- Kiwi, g2pkk, jamo, fastText 한국어 벡터, Polyglot-Ko 1.3B가 이 PC(Windows)와 GPU 머신(Linux)에서 돌아가는지 본다.
- g2pK가 단어 단독으로 낸 발음과 문장 속 발음이 다른 경우(예: 조사가 붙어 연음되는 경우)를 확인한다.
- **기준**: 다섯 도구 모두 설치되고, 표준 발음 예시 20개(직접 고른 것)를 g2pK가 맞힌다.

### K1 쌍 목록 (CPU)
- 빈도 상위 명사 → g2pK 발음 → 자모·IPA 거리 → 거리 0(철자 다름, 발음 같음)과 거리 1 쌍.
- 거르기: 표제어 다름(Kiwi), 뜻 거리(fastText cos), 2음절 이상, 비속어·고유명사 제외. 영어처럼 정규화 거리 ≤ 0.4.
- **기준**: 거리 0 쌍이 30개 이상, 거리 1 쌍이 수백 개 이상. 거리 0이 너무 적으면 1단계는 거리 1 위주로 가고 그 사실을 적는다.
- 표본: 파일럿 10쌍, 본 실행 40쌍(영어와 같은 크기), 거리별 반씩.

### K2 한국어 말장난 자료 만들기 (네가 직접, 가장 중요한 단계)
영어에는 SemEval(말장난 + w_p/w_a 주석)과 He 자료(말장난 vs 단어만 바꾼 문장 + 사람 웃김 점수)가 있었다. 한국어에는 찾지 못했다.
- **K2a 말장난 모음**: 한국어 말장난 100~150개. 각각 w_p, w_a, 종류(1절의 표), 형식(퀴즈/한 줄)을 적는다. 철자가 다른 근접 동음 종류가
  최소 60개는 있어야 한다.
  - 출처: 네가 직접 쓰거나 기억나는 흔한 것. 웹에서 모은 것은 저작권 문제가 있을 수 있어 **공개 저장소에는 직접 쓴 것만** 올리고, 나머지는 로컬(`data/`, gitignore)에 둔다.
- **K2b 대조 문장**: 각 말장난에서 w_p를 w_a로 바꾼 문장(영어 He의 depun)을 코드로 만든다.
- **K2c 라벨**: K2a·K2b 문장을 블라인드로 섞어 성립(예/아니오)과 웃김(1~5)을 매긴다. 이 라벨이 관문 문턱, 판정기 검증, 네 평가의 일관성 확인에 함께 쓰인다.
- 한계: 자료를 만든 사람과 평가하는 사람이 같다. 문턱은 자료로 맞추고, 본 실행 평가는 따로 하므로 순환은 피하지만, 취향의 편향은 남는다.

### K3 청자 모델 검증 (GPU 조금)
- Polyglot-Ko로 K2a 말장난의 w_a를 되찾는지 본다(영어 E1과 같은 질문): w_a가 발음 후보 중 몇 위인가, 우연보다 나은가.
- γ와 관문 문턱을 K2(말장난 vs 대조 문장)에서 맞춘다.
- **기준**: 말장난에서 w_a 1위 비율이 우연보다 뚜렷이 높다. 아니면 청자 모델부터 다시 본다(더 큰 모델, KORMo 등).

### K4 파일럿 (GPU)
- 영어 파일럿 4의 설정을 그대로 옮긴다: S1 상한 60, 칸당 후보 10, 조건 B0·B1·P1~P4, 기준 C1~C3 + 판정기 기준.
- 생성기 후보 두 개를 같은 쌍으로 돌려 고른다.
- 판정기: K2 라벨로 검증한 뒤 쓴다(영어 `judge_validate.py`의 V1·V2를 한국어 자료로).

### K5 사전 등록과 본 실행
- `PREREG_K.md`를 쓰고 태그를 단 뒤 본 실행(40쌍 × 2형식 = 80칸).
- 사람 평가: 영어용으로 짠 단일 평가자 설계(칸 단위 블라인드, 문장마다 w_p 뜻·w_a 뜻·성립, 칸 안 웃김 순위, 재검사).

## 4. 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 철자가 다른 같은 소리 쌍이 적다 | 1단계 범위가 좁아진다 | K1에서 먼저 센다. 적으면 거리 1 위주로 |
| 한국어 말장난 자료가 없다 | γ·문턱·판정기 검증을 할 근거가 없다 | K2에서 직접 만든다. 시간이 가장 많이 든다 |
| 조사·어미 처리 | S2와 청자 채점이 어긋난다 | 1단계는 명사만, 조사 이형태 규칙으로 |
| 문장 속 발음 변화 | 단어 단독 발음 거리와 실제 들리는 소리가 다르다 | 청자 후보를 문장 속 발음으로도 확인(K0) |
| 생성기의 한국어 말장난 능력 | 영어 파일럿처럼 여러 번 돌 수 있다 | 영어에서 얻은 장치(S1 상한, 넣기 vs 바꾸기 등)를 처음부터 넣는다 |
| Windows에서 MeCab | g2pK, wordfreq 한국어가 막힌다 | g2pkk, Kiwi 사용, 또는 GPU 머신(Linux)에서 전처리 |

## 5. 정해야 할 것 (네 결정)

1. **범위**: 1단계를 철자가 다른 근접 동음 쌍만으로 할지(추천), 같은 철자 동음이의어(사과, 배)까지 할지.
2. **K2 자료**: 말장난 100~150개를 직접 모으고 주석할 수 있는지. 이게 안 되면 관문과 판정기를 검증할 방법이 없다.
3. **저장소**: 이 저장소에 `ko/` 계열로 둘지(코드 재사용이 쉽다, 추천), 새 저장소로 뺄지.
4. **영어 E5 본 실행**: 한국어로 넘어가기 전에 영어 본 실행을 끝낼지, 멈춰 두고 한국어로 갈지.
